## 0. ⚠️ 先说一个必须纠正的选型冲突

### 0.1 问题：RuoYi-Vue-Pro 用 Spring Security，但你们选了 Sa-Token

**RuoYi-Vue-Pro（芋道 yudao）的后台认证是 Spring Security + JWT**，而你们定稿的选型是 **Sa-Token**。这是**两套互不兼容的认证体系**：

| 硬凑的后果 | 说明 |
|---|---|
| 两套认证框架并存 | 后台走 Spring Security，前台走 Sa-Token，两套 FilterChain、两套登录态、两套权限模型 |
| 登录态无法互通 | 运营在前台测试作品要再登一次 |
| 代码风格割裂 | 团队要在两套心智模型间切换 |
| 升级困难 | RuoYi 上游更新会不断冲击你的改造 |

### 0.2 ✅ 建议：把 RuoYi-Vue-Pro 换成 **RuoYi-Vue-Plus**

**RuoYi-Vue-Plus（dromara 社区，最新 v5.2.3）的技术栈与你们定稿的选型几乎完全对齐**：

| 能力 | RuoYi-Vue-Plus | RuoYi-Vue-Pro（芋道） | 你们的选择 |
|---|---|---|---|
| 认证 | **Sa-Token** ✅ | Spring Security ❌ | **Sa-Token** |
| 缓存 | **Redisson** ✅ | Redis（部分 Redisson） | **Redisson** |
| ORM | **MyBatis-Plus** ✅ | MyBatis-Plus ✅ | **MyBatis-Plus** |
| 多端登录 | Sa-Token 原生 ✅ | 需改造 | 需要 |
| 幂等 | 内置 `common-idempotent` ✅ | 需自研 | 需要（解锁/扣费） |
| 工作流 | Warm-Flow ✅ | Flowable | 作品审核流 |
| 代码生成 | ✅ | ✅ | 需要 |

**更关键的是**：我当初推荐芋道的理由是"自带支付 + 短信模块，省 2 个月"。但你们最终选了 **IJPay** 和 **SMS4J** —— 芋道内置的支付/短信模块**本来就要被替换掉**。所以芋道真正的优势（支付/短信/商城/CRM）全部用不上，而它的劣势（Spring Security）却要实打实承担。

> **结论：采用 RuoYi-Vue-Plus 作为后台底座，而不是 RuoYi-Vue-Pro。** ✅ **已确认切换**
> 如果团队已经基于芋道做了调研，请在 M1 前切换，越早越好。

### 1.4 ⚠️ Redis Stack 的重要变化

> **你选的"Redis + Redisson"和"Redis Stack"其实是同一个东西了。**

**Redis 8.0 已经把 Redis Stack 的模块（RediSearch / RedisJSON / RedisTimeSeries / RedisBloom）内置进核心发行版**。所以：

| 旧方案 | 新方案 |
|---|---|
| Redis 7 + 单独的 Redis Stack 镜像 | **Redis 8.0 一个镜像搞定**，RediSearch 与向量检索开箱可用 |
| 部署两个 Redis 实例 | **一个实例** |

**落地建议**：
```bash
# 直接用 Redis 8，向量检索与 Redisson 兼容
docker run -d --name kjx-redis -p 6379:6379 redis:8-alpine
```

**许可证提醒**：Redis 8 提供**三选一**许可（AGPLv3 / RSALv2 / SSPL）。**自用不受影响**；若公司政策禁止，可换 **Valkey 8**（BSD-3，协议兼容，但需确认 RediSearch 模块是否齐备）。

### 2.2 依赖管理策略（关键）

**规则：三层版本管理，越靠上越优先。**

```
① 父 POM 的 <parent> = spring-boot-starter-parent:3.5.16
   → 管理 Spring 全家桶版本（含 Flyway、Jackson、HikariCP 等）

② 父 POM 的 <dependencyManagement> 引入各 BOM
   → spring-ai-bom:1.1.5
   → mybatis-plus-bom:3.5.17
   → redisson-bom:4.7.0（若提供）
   → liteflow-bom
   → 各组件 BOM

③ 子模块 <dependencies> 只写 groupId + artifactId
   → 一律不写 <version>
```

**父 POM 核心片段**：

```xml
<parent>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-parent</artifactId>
  <version>3.5.16</version>
  <relativePath/>
</parent>

<properties>
  <java.version>21</java.version>
  <maven.compiler.release>21</maven.compiler.release>
  <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>

  <spring-ai.version>1.1.5</spring-ai.version>
  <mybatis-plus.version>3.5.17</mybatis-plus.version>
  <redisson.version>4.7.0</redisson.version>
  <sa-token.version>1.46.0</sa-token.version>
  <liteflow.version>2.13.x</liteflow.version>
  <!-- 其余… -->
</properties>

<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>org.springframework.ai</groupId>
      <artifactId>spring-ai-bom</artifactId>
      <version>${spring-ai.version}</version>
      <type>pom</type><scope>import</scope>
    </dependency>
    <dependency>
      <groupId>com.baomidou</groupId>
      <artifactId>mybatis-plus-bom</artifactId>
      <version>${mybatis-plus.version}</version>
      <type>pom</type><scope>import</scope>
    </dependency>
    <!-- 其余 BOM… -->
  </dependencies>
</dependencyManagement>
```

### 2.3 需要替换/改造的 RuoYi-Vue-Plus 内置能力

| RuoYi-Vue-Plus 内置 | 替换为 | 改造点 |
|---|---|---|
| `ruoyi-common-oss` | **X-File-Storage** | 保留接口，底层换成 XFS（未来换云厂商零改代码） |
| 内置短信 | **SMS4J** | 保留发送入口，底层换 SMS4J（多厂商聚合） |
| 内置登录/权限 | **Sa-Token 扩展** | RuoYi-Vue-Plus 已用 Sa-Token，只需扩展「会员」端登录类型 |
| 内置定时任务 | **Redisson 延迟队列**（并存） | 定时任务用 RuoYi 的；**延迟任务**用 Redisson |
| 内置对象存储配置页 | 保留（管理云存储密钥） | — |

### 2.4 依赖冲突预警清单（M1 必须验证）

| 冲突点 | 风险 | 验证方式 |
|---|---|---|
| **Redisson 4.x** 与 Spring Boot 3.5 | 4.x 是大版本跃迁，可能有 API 破坏性变更 | 最小工程跑通锁/限流/延迟队列；**不通过则回退 Redisson 3.4x**（`RLock`/`RRateLimiter`/`RDelayedQueue` API 基本一致） |
| **Sa-Token** 与 RuoYi-Vue-Plus 的 Sa-Token 版本 | 版本不一致会导致自动配置冲突 | 统一到 RuoYi-Vue-Plus 使用的版本或升级全套 |
| **Spring AI 1.1.5** 与 Spring Boot 3.5.16 | Spring AI 1.1.x 面向 Boot 3.4/3.5，一般兼容 | 跑通一次结构化输出 + Tool Calling |
| **MySQL 驱动** 与 Boot 3.5 | 用 `com.mysql:mysql-connector-j`（新坐标） | — |
| **LiteFlow** 与 Spring Boot 3.5 | 需确认 starter 名（`liteflow-spring-boot-starter`） | 跑通一条 EL 链 |
| **tianai-captcha** 许可证 | **待核实**（GPL 风险） | 若是 GPL，换 AJ-Captcha（Apache-2.0） |

### 3.2 模块职责与边界

| 模块 | 职责 | 对外提供 | 依赖 |
|---|---|---|---|
| `kjx-account` | 注册、登录、验证码、会话、设备管理、账号注销 | 账号 API、认证上下文 | common-satoken、SMS4J、tianai-captcha |
| `kjx-member` | 三要素绑定、后台会员授权、权益、解锁额度 | 会员 API、绑定 API、**权益校验服务** | account、work |
| `kjx-work` | 作品/版本/内容库/素材库/音乐库/作品包上传校验 | 作品 API、内容下发服务、素材签名服务 | XFS、FFmpeg、Thumbnailator |
| `kjx-runtime-api` | Runtime/Tool 共享的中立端口、DTO、错误类型；不得包含实现与 Mapper | `SessionStatePort`、`SessionAuthorizationPort`、`ToolExecutionPort`、`EntitlementAccessPort` | common-core |
| `kjx-runtime` | 会话与游戏运行时、存档、分段披露、布局数据下发；实现 runtime-api 中的状态与会话端口 | 运行时 API、存档 API | work、ai、runtime-api |
| `kjx-ai` | Prompt 组装（稳定前缀+可变后缀）、会话记忆、结构化输出、模型路由 | AI 调用服务、Prompt 管理 | Spring AI、channel、Langfuse |
| `kjx-tool` | 原子能力注册、内置工具库、自定义工具编排（LiteFlow）、工具执行与前置校验；实现 `ToolExecutionPort` | 工具注册表、工具执行服务 | ai、runtime-api、billing、member |
| `kjx-channel` | 双通道解析、BYOK 凭据管理、网关适配、SSRF 防护 | 通道解析服务、凭据管理 | Redisson、Bouncy Castle |
| `kjx-billing` | 计量、双录账本、冻结结算、订单、支付、对账 | 计费服务、订单 API、支付回调 | IJPay、channel |
| `kjx-log` | 12 类日志落库、检索、归档、留存策略 | 日志写入 SDK、日志检索 API | MySQL、ClickHouse |

**模块间调用规则**：
1. **同进程内方法调用**（模块化单体），只依赖目标模块公开的 `api/port`，禁止跨模块访问 `Mapper`、Entity 或内部 Service。
2. **禁止循环依赖**：`runtime` 与 `tool` 都只依赖 `runtime-api`；二者不得直接相互依赖。该规则必须由 Maven Enforcer/ArchUnit 在 CI 中强制。
3. **强一致写同事务**：绑定审核、解锁、人工权益调整、账本与关键 `AUDIT` 必须在同一个 MySQL 事务内完成。
4. **副作用走 Transactional Outbox**：短信、站内信、ClickHouse 投影、统计等在业务事务内只写 `kjx_outbox_event`，提交后由消费者至少一次投递并幂等处理。
5. Spring `ApplicationEvent` 仅可用于事务提交后的进程内唤醒或非关键通知，**不能替代持久化 Outbox**。

## 4. 关键数据流

### 4.1 会员绑定（三要素）

```
前端提交(抖音号 + 已订阅月数 + 会员编码)
    │
    ▼
kjx-account：校验登录态（Sa-Token）
    │
    ▼
kjx-member.BindingService
    ├─ 规范化三要素（trim/去@/小写/大写编码）
    ├─ 查询 member：member_code + douyin_id + subscribed_months 三者同时匹配
    │     └─ 未命中 → 统一提示「信息不匹配」+ 失败计数（Redisson RRateLimiter）
    ├─ 校验 member_binding 唯一性（UNIQUE(account_id) + UNIQUE(member_id)）
    ├─ 人工审核开关（全局配置）
    │     ├─ 需审核 → 写 member_binding(status=PENDING_REVIEW)
    │     └─ 直接通过 → 写 member_binding(status=MATCHED) + 锁定 member
    ├─ 同事务写通知 Outbox（站内信 + 短信事件）
    └─ 写 BIZ + SEC 日志
    │
    ▼
返回绑定结果，前端跳转作品选择页
```

### 4.2 解锁作品（原子性）

```
前端点击「解锁」→ 二次确认 → POST /app/works/{workCode}/unlock
    │
    ▼
kjx-member.UnlockService（@Transactional + @Idempotent）
    ├─ ① 登录态校验
    ├─ ② 会员状态校验（VALID）
    ├─ ③ CAS 更新：UPDATE member SET unlocked_count = unlocked_count + 1
    │        WHERE id = ? AND unlocked_count < available_count AND status = 'VALID'
    │        → 影响行数 = 0 则返回失败（额度用完）
    ├─ ④ INSERT member_entitlement（UNIQUE(member_id, work_id) 兜底并发）
    ├─ ⑤ INSERT unlock_record（含前后快照 + source='user'）
    └─ ⑥ 写 BIZ 日志
    │
    ▼
成功 → 返回作品入口信息 → 前端跳转运行时界面
```

> **MySQL 隔离级别提醒**（REPEATABLE READ 下）：**必须用第 ③ 步的单条 CAS 语句**，禁止"先 SELECT 判断再 UPDATE"。

### 4.3 AI 对话（双通道）

```
前端 POST /v1/chat/completions（SSE）
    │  Header: X-KJX-Session-Id / X-KJX-Work-Id / X-KJX-Channel / [X-KJX-BYOK-Key]
    ▼
Higress AI 网关
    ├─ 鉴权（平台虚拟 Key / 会话令牌）
    ├─ 限流（QPS + Token/分钟）
    └─ 路由到 kjx-server
    │
    ▼
kjx-channel.ChannelResolver → 决定通道（界面 > 作品 > 用户默认 > 平台默认）
    │
    ▼
kjx-billing：平台通道 → 预授权冻结额度
    │
    ▼
kjx-ai.PromptAssembler
    ├─ 稳定前缀：人设 + 叙事规则 + 工具定义（★ 尽量不变，命中 Prompt 缓存）
    ├─ 可变后缀：当前状态 + 记忆摘要 + 最近 N 轮对话
    └─ 注入 secretRef 字段（永不下发前端）
    │
    ▼
kjx-ai.ModelRouter → 按任务选模型
    ├─ 主对话 → 强模型
    └─ 意图判定/落子/评论 → 廉价模型
    │
    ▼
Spring AI ChatClient → 上游模型（平台 API 或 用户 BYOK 网关）
    │
    ▼
返回含 tool_call → kjx-tool.ToolExecutor
    ├─ 参数 Schema 校验
    ├─ 前置条件校验链（登录 → entitlement → 会话归属/状态 → 频次 → 单回合上限）
    │   └─ 已解锁作品为买断权益：Tool 不校验 member.status；VALID 仅用于“新解锁”
    ├─ LiteFlow 执行原子能力编排
    ├─ 内容安全（sensitive-word → 云厂商 API）
    ├─ 写状态 + 产出声明式 UI 指令
    └─ 写 TOOL_CALL 日志
    │
    ▼
结果回填给模型 → 最终回复
    │
    ▼
kjx-billing：按 usage 结算（平台通道扣费 / BYOK 计 0）
kjx-log：写 AI_CALL 日志
Langfuse：旁路上报 trace + prompt 版本 + 成本
    │
    ▼
SSE 流式返回前端 → 前端渲染器按 UI 指令渲染
```

### 4.4 工具执行（LiteFlow 编排）

```
模型输出 tool_call(rewrite.message, {...})
    │
    ▼
kjx-tool.ToolExecutor
    ├─ ① 查工具注册表（tool_name + tool_version）
    ├─ ② JSON Schema 校验参数
    ├─ ③ 前置条件校验链（任一失败 → 返回结构化拒绝原因）
    ├─ ④ 按 implementation.kind 执行
    │     ├─ builtin → 平台实现类
    │     └─ compose → LiteFlow 执行 EL 链
    │           · 原子能力组件（store/state/content/schedule/notify/asset/ui/llm/rule）
    │           · 支持 THEN/IF/SWITCH/FOR/WHILE/WHEN
    │           · 事务：@Transactional 标在组件上
    ├─ ⑤ 内容安全审核
    ├─ ⑥ 写状态 + 产出 ui[] 指令
    └─ ⑦ 写 TOOL_CALL 日志（入参/前置判定/步骤轨迹/耗时）
    │
    ▼
返回 { ok, ui[], state, hint }
```

### 4.5 计费（冻结 → 结算）

```
调用前
    ├─ 估算上限 = messages token + max_tokens
    └─ Redisson RLock + wallet 行锁 → 冻结（frozen += 估算值）

调用后
    ├─ 按上游 usage 计算实际消耗
    ├─ 结算：frozen -= 估算值；balance -= 实际值
    ├─ INSERT ledger_entry（append-only，idempotency_key UNIQUE）
    ├─ INSERT usage_event（归因到 work/session/turn）
    └─ 释放剩余冻结

每日 03:00 对账任务
    ├─ 内部对账：ledger_entry ↔ usage_event
    ├─ 外部对账：与支付宝/微信账单、与上游模型账单
    └─ 差异 → reconcile_record + 告警
```

## 8. 安全边界

| 边界 | 措施 |
|---|---|
| 外网 → Nginx | HTTPS 强制、WAF、限流 |
| Nginx → Higress | 内网、白名单 |
| Higress → kjx-server | 内网、服务令牌 |
| **kjx-server → 用户 BYOK 网关** | **SSRF 黑名单**（内网/保留地址拒）、仅 80/443、仅 HTTPS、Key 脱敏不落日志 |
| kjx-server → 云服务 | 密钥走环境变量 / KMS；最小权限 RAM |
| **数据边界** | 全部在国内；**平台内部通道不走境外模型**（BYOK 由用户自担，见 07 D-29） |
| 沙箱作品 → 平台 | 独立子域 iframe + `sandbox` + postMessage + CSP |
| 管理后台 | 独立路径 `/admin/**`、IP 白名单（可选）、2FA |

**加密**：
- 密码：bcrypt / Argon2
- BYOK Key（`MANAGED` 档）：AES-256-GCM 信封加密（KMS 主密钥 + 数据密钥）
- 存档：checksum + 签名
- 审计日志：链式哈希

## 10. 版本升级策略

| 组件 | 升级节奏 | 注意 |
|---|---|---|
| **Spring Boot 3.5.x** | 跟随补丁版（3.5.17、3.5.18…） | 只升补丁，不跨小版本 |
| **Spring Boot 3.5 → 4.x** | **暂不升** | 国产库适配滞后（详见归档选型 §7.2） |
| **Spring AI 1.1.x** | 跟随补丁版 | 不升 2.0（需 Boot 4） |
| **RuoYi-Vue-Plus** | 按需合并上游 | 合并前先跑回归；自研模块与上游解耦 |
| **MySQL 8.4** | 跟随 LTS 补丁 | 不跨到 9.x |
| **Redis 8** | 跟随补丁 | 注意 AGPL 条款变化 |
| **Higress** | 跟随小版本 | 升级前备份配置 |

**依赖升级流程**：`升级 → 跑单元测试 → 跑集成测试（Testcontainers）→ 部署 staging → 压测 → 灰度 → 全量`
